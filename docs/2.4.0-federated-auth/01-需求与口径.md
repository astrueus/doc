# 01 · 需求与口径

## 需求

Round 5 T16：把挤在 `AccountController` 里的钉钉登录抽成可扩展的外部登录，并加上企业微信。原细化稿把整层叫「OAuth2 Provider」，接第三家会再次复制粘贴，且现网「全员共用 `tmp_reader`」无法一人一号。

知识库口径（[身份认证](https://doc.itopcms.com/docs/backend/backend-1f3sb20d3sq42)）：

- 认证认人，授权定权；OAuth 2.0 是授权，OIDC 才是登录身份。
- 对外用户登录优先 **Session + Cookie**；不要把第三方 Access Token 当身份断言。
- 企业 SSO 新系统优先 OIDC；SAML 另议。

本仓库现状：浏览器已是 Session（只存 `member_id`）；MCP 已是可吊销不透明 Token。联邦登录结束后必须落到这两套，而不是 JWT。

## 已确认（2026-09-01）

| # | 口径 | 说明 |
|---|------|------|
| 1 | **身份表 + 一人一号** | `md_member_identities`，`UNIQUE(provider, subject)` → `member_id`。不存在则按配置自动建号或拒绝。 |
| 2 | **不兼容旧钉钉绑定** | 删除 `dingtalk_tmp_reader`、联邦路径上的 `TmpLogin`。不为「行为回归」保留共用临时读者。 |
| 3 | **本期范围** | 内核 + 钉钉 + 企微网页授权。钉钉 HTTP 客户端 **F1 一并内聚**，删除 `internal/thirdparty/dingtalk`。通用 OIDC 只留接口，不落地。 |
| 4 | **新路由，旧路由删除** | 现网无外部登录可依赖。删除 `/dingtalk_login`、`/qrlogin/:app`，统一 `/login/federated/{provider}` 与 `/callback`。 |
| 5 | **Doc 是 RP，不是授权服务器** | 换完票只抽出 `Identity`，Access Token 不写 Session。 |
| 6 | **凭证登录并列** | 本地密码 / LDAP / `http_login_url` 仍走 `Member.Login`，不进联邦 Registry。 |
| 7 | **硬切配置** | 联邦项进 `[auth]` / `[oauth.dingtalk]` / `[oauth.wework]`。不再读旧 `[dingtalk]` section 与 `DOC_DINGTALK_READER`。 |
| 8 | **自动建号默认开** | `auth.auto_create_member=true`。无邮箱时用合成邮箱；`auth_method=federated`，不可用空密码走本地登录。 |
| 9 | **角色** | 自动建号角色与 LDAP 默认一致：`ldap_user_role` 同档（普通用户 `2`），可用 `auth.default_role` 覆盖。 |

## 未决

无阻塞项。落实前若生产其实仍开着钉钉旧回调，须先改 IdP 后台 Redirect URI（见 05），再发版。

## 边界

| 做 | 不做 |
|----|------|
| 联邦 `Start` / `Complete` / Binder / Session | 换绑 UI、按邮箱自动合并已有 local 账号 |
| 钉钉：应用内 code + 扫码授权码（真 `state`）；客户端内聚进 federated，删除 `thirdparty/dingtalk` | 钉钉免登继续共用一个读者；先包装旧包再下轮删除 |
| 企微：网页授权取 UserId | 企微独立扫码 JS 组件（可后补，仍走同一 `Complete`） |
| 登录页按 Registry 出按钮/二维码 | 改 MCP 鉴权方式 |
| 迁移建表（MySQL + SQLite） | 历史「钉钉临时读者」数据迁移（无外部登录、无绑定可迁） |
