# 02 · 现状分析

## 认证面一览

| 面 | 实现 | 结论 |
|----|------|------|
| 浏览器 Session | `BaseController.SetMember` 只存 `member_id`；`auth.MemberIDFromSession` | **保持**。联邦登录成功后只调这一套。 |
| MCP | `member_api_tokens` + sha256；`MemberRepo.ResolveAPIToken` | **不改**。用户登录后再签发。 |
| 本地密码 | `Member.Login` → `PasswordVerify` | **不改**。 |
| LDAP | `Member.ldapLogin` | **不改**。 |
| HTTP 账密转发 | `[oauth] http_login_url` / `httpLogin` | **不改**，不要并进联邦 Registry。 |
| 钉钉 | Controller 内联 + `internal/thirdparty/dingtalk` | **Controller 与 thirdparty 包一并删除**；HTTP 调用迁入 `federated/dingtalk.go`。 |
| 企业微信 | 无 | **本期新增 Provider**。 |

## 钉钉现链路（问题）

### 应用内

1. 登录页 `web/views/account/login.tpl` 在钉钉 JSAPI 里拿到 `info.code`。
2. POST `/dingtalk_login` → `AccountController.DingTalkLogin`（`internal/controller/AccountController.go`）。
3. `GetUserIDByCode` / `GetUserNameAndAvatarByUserID`。
4. **`TmpLogin(dingtalk_tmp_reader)`**：查出**同一个**本地账号，改 `Account`/`Avatar` 后 `SetMember`。

全员共享一个读者，审计、权限、MCP Token 都对不上真人。

### 扫码

1. 路由 `/qrlogin/:app` → `QRLogin`，`app=dingtalk`。
2. 要求 `state == "1"`（**不是 CSRF 随机数**）。
3. `GetUnionIDByCode` → `GetUserIDByUnionID` → 仍走 `TmpLogin`。

钉钉开放平台 Redirect URI 若曾配成该路径，发版后改为 `/login/federated/dingtalk/callback`。

### 配置

`conf/app.conf.example` `[dingtalk]`：`DOC_DINGTALK_CORPID` / `APPKEY` / `APPSECRET` / **`READER`** / `QRKEY` / `QRSECRET`。  
`config.DingTalkSection.TmpReader` 对应 `dingtalk_tmp_reader`。本期删除 Reader 与整段 `[dingtalk]`。

## `Member.Add` 对联邦的约束

`Add` 要求账号匹配 `RegexpAccount`（字母数字 3–50）、邮箱格式且唯一；`auth_method=local` 时还要密码。联邦建号**不能**直接调 `Add`，须走 Repo 专用插入（随机不可用密码哈希或空密码 + `auth_method=federated`）。

## 现网 `state` 与知识库差距

知识库要求 `state` 防 CSRF。现扫码 `state=1` 可被固定重放。本期：密码学随机、单次、写入 Session，回调校验失败则拒。
